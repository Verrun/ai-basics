# Ф3. HTTP, JSON, DevTools: как работает API

## За 2 минуты

В Ф1 ты узнала: **API** — это официант, который передаёт заказы между фронтендом и бекендом. Этот официант говорит на строгом языке — **HTTP** (HyperText Transfer Protocol, «протокол передачи гипертекста»). У каждого «письма» есть адрес (**URL**) и намерение (**метод**: GET — «покажи», POST — «отправь»). На письмо приходит ответ со **статус-кодом**: 200 — «получилось», 404 — «не нашлось», 500 — «кухня сломалась». Данные ездят в стандартном формате **JSON** — как анкета, которую понимают обе стороны. А **DevTools** (вкладка Network в Chrome) — это рентген сайта: через неё видно все реальные запросы.

---

## Простыми словами

Представь, что API-официант из Ф1 передаёт заказы **почтовыми открытками**. Эти открытки ходят по правилам, и правила эти называются **HTTP**.

Каждая открытка состоит из двух обязательных частей:

1. **Адрес (URL)** — куда нести. Как адрес на конверте: `ресторан.ru/окошко-заказов`. В интернете это выглядит так: `api.site.com/users` — адрес сайта + конкретное «окошко» (**endpoint**).
2. **Метод** — что ты хочешь. Это одно слово на открытке, и оно определяет смысл всего письма:
   - **GET** — «покажи мне…» (принеси меню, покажи мой заказ)
   - **POST** — «вот, прими…» (отправь заказ на кухню, создай нового пользователя)
   - **PUT** — «замени…» (заказ был паста, теперь пицца)
   - **DELETE** — «удали…» (отмени заказ)

Кухня получает открытку, делает своё и **отвечает обратной открыткой**. На обороте — число, которое называется **статус-код**. По нему ты сразу понимаешь, что случилось, даже не читая текст:

- **2xx** (например, **200**) — «получилось, держи».
- **4xx** — «ты что-то перепутала»: **404** — «такого блюда в меню нет» (страница не нашлась), **403** — «тебе сюда нельзя» (нет доступа).
- **5xx** (например, **500**) — «у нас на кухне пожар» (сервер сам сломался).

А внутри открытки лежит **JSON** — стандартная анкета. Почему именно она? Потому что на кухне и в зале говорят на разных «языках» (разных языках программирования), а анкета устроена так, что её понимают все: одно поле — одно значение, понятно, где что. Это как бланк в банке: не важно, кто его заполнил, важно, что все поля на своих местах.

Теперь главное: **всё это можно увидеть своими глазами**. В браузере Chrome есть **DevTools** (инструменты разработчика) — рентген сайта. Вкладка **Network** показывает каждую «открытку», которую сайт отправил и получил, с адресами, методами, статус-кодами и содержимым. После этого урока ты больше никогда не будешь смотреть на сайты как раньше.

## Объяснение

### HTTP: язык почтовых открыток

**Термин:** **HTTP** (HyperText Transfer Protocol) — набор правил, по которым браузер и сервер обмениваются «письмами»: запрос → ответ. Никогда не одиночные слова — всегда пара: попросила → получила ответ.

**Термин:** **URL** — полный адрес ресурса: `https://api.shop.com/orders/42` — где (`api.shop.com`), какое окошко (`/orders`) и какой именно заказ (`/42`).

Схема одного обмена:

```
Ты (браузер)                Сервер (кухня)
      │  GET /menu  ──────────────►│
      │                            │  ищет, проверяет, считает
      │◄────────────  200 OK + JSON│
      │                            │
```

### Методы: четыре намерения

**Термин:** **метод** (method) — слово, которым начинается запрос и которое означает намерение.

| Метод | Перевод | Аналогия | Пример |
|-------|---------|----------|--------|
| **GET** | «покажи» | Попросить меню | Загрузить ленту, список товаров |
| **POST** | «прими / создай» | Отправить заказ | Оформить покупку, залогиниться |
| **PUT** | «замени» | «Вместо пасты — пицца» | Обновить профиль, изменить адрес |
| **DELETE** | «удали» | Отменить заказ | Удалить черновик, отписаться |

Два метода покрывают 95% того, что ты делаешь в интернете: листаешь — **GET**, отправляешь форму — **POST**.

### Статус-коды: что ответила кухня

**Термин:** **статус-код** — трёхзначное число в ответе сервера. Первая цифра говорит о категории:

| Код | Что значит | Аналогия |
|-----|------------|----------|
| **200** | Успех, вот данные | «Блюдо готово, держи» |
| **301/302** | Адрес переехал | «Мы переехали в соседний дом» |
| **403** | Запрещено | «Вашего имени нет в списке гостей» |
| **404** | Не найдено | «Такого блюда в меню нет» |
| **500** | Ошибка сервера | «На кухне пожар — повара переругались» |

Правило на всю жизнь: **4xx — ошибка на твоей стороне** (неправильный адрес, нет прав), **5xx — поломка на их стороне**. Это первое, что смотрит любой разработчик.

### JSON: стандартная анкета

**Термин:** **JSON** (JavaScript Object Notation) — текстовый формат для передачи данных: пары «поле: значение».

```json
{
  "name": "Аня",
  "age": 30,
  "premium": true
}
```

Прочитай как анкету: поле **name**, значение **«Аня»**; поле **age**, значение **30**; поле **premium**, значение **«да, true»**. Кавычки, двоеточия и запятые — это рамки бланка, чтобы машина не перепутала, где поле, а где значение.

| | Почему JSON, а не «свой формат» |
|--|----------------------------------|
| Понятен всем языкам | Кухня на Python, зал на JS — обе читают один бланк |
| Читается человеком | Ты видишь слова, а не непонятную кашу |
| Лёгкий | Только текст, без лишнего |

Тебе не нужно писать JSON руками — Agent это делает за тебя. Тебе нужно **уметь читать** его глазами: найти поле и понять его значение.

### DevTools: рентген сайта

**Термин:** **DevTools** (Developer Tools, «инструменты разработчика») — панель внутри браузера, показывающая, как устроен сайт изнутри. Нам нужна вкладка **Network** (сеть) — журнал всех запросов.

Это самый полезный навык урока:

1. Открой любой сайт в Chrome.
2. Нажми **F12** (на Mac: **Fn + F12** или правый клик → «Просмотреть код»). Появится панель.
3. Перейди на вкладку **Network**.
4. **Обнови страницу** (F5) — и наблюдай: перед тобой оживает список всех «открыток», которые сайт отправил.
5. Кликни по любой строке со словом **GET** в колонке Method — откроется карточка запроса:
   - **Headers** (заголовки) — адрес, метод, статус-код;
   - **Response** / **Preview** (ответ) — что прислал сервер, часто в JSON.

Теперь ты видишь то, что раньше было скрыто: сколько запросов делает один сайт (обычно десятки), какие из них «достали» товары, а какие — картинки.

### Ловушки

1. **Путать 404 и 500** — 404: «такой страницы нет» (ты ошиблась адресом); 500: «сайт сломался сам» (его чинят). Это разные миры и разные действия.
2. **Судить по скриншоту вместо текста** — красная плашка «Ошибка» ничего не говорит. Смотри **статус-код и текст ответа** в DevTools — они говорят точно, что случилось.
3. **Вставлять токены из запросов в чекеры и чаты** — в заголовках запросов видны твои **токены доступа** (пропуска). Скопировала их в сторонний сервис — отдала ключи от своего аккаунта.
4. **Думать, что метод не важен** — GET и POST с одним адресом — это два разных «окошка» с разным смыслом. Адрес один, намерение разное.
5. **Паниковать от кода ответа 4xx в DevTools** — некоторые 404 в журнале — это норма (сайт проверял, есть ли картинка). Смотри на контекст, а не на одно число.
6. **Искать «где кнопка» вместо «какой запрос»** — когда что-то не работает, смотри в Network, **какой запрос упал**, а не куда жать на экране.

## Практика

Главная практика курса: ты впервые видишь API изнутри.

1. Открой в Chrome любимый сайт (почта, маркетплейс, соцсеть — где ты залогинена).
2. Нажми **F12** → вкладка **Network**.
3. Обнови страницу (**F5**). Посмотри на список запросов: сколько их? (Обычно 30–100.)
4. Найди в колонке Method запрос **GET**, кликни по нему. В карточке запиши:
   - **адрес** (URL) — на какое «окошко» стучались;
   - **статус-код** — что ответила кухня;
   - в Response/Preview найди, какие **поля JSON** пришли (например, `name`, `price`).
5. Теперь сделай действие на сайте (открой товар, обнови ленту) **не закрывая DevTools** — и посмотри, какой новый запрос появился в списке. Это и есть «путь одного клика» из Ф1, только настоящий.
6. Бонус: поставь галочку **Disable cache** (отключить кэш) вверху вкладки Network, обнови страницу и сравни время загрузки. Кэш — это когда официант запоминает заказ, чтобы не бегать на кухню заново.

## Частые ошибки

1. **Читать скриншот, а не код** — белое окно с ошибкой — это симптом; статус-код и текст ответа в DevTools — диагноз.
2. **Копировать запросы целиком в чаты** — в них сидят твои токены. Делись адресом и статус-кодом, секреты замазывай.
3. **Путать «не нашлось» и «сломалось»** — 404 чинится исправлением адреса, 500 — ждёт починки на их стороне.
