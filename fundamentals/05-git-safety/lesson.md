# Ф5. Git: коммиты, diff, ветки, remote и безопасный откат

## За 2 минуты

**Git** — это **машина времени** для папки с файлами плюс **черновики**. Каждый **коммит (commit)** — снимок состояния папки с подписью и уникальным номером (**хеш**), к которому всегда можно вернуться. **Diff** показывает разницу между снимками, **ветка (branch)** — параллельный черновик, **merge** вписывает черновик в чистовик, **remote** (GitHub) — облачная копия тетради. Откатываться безопасно: в общих ветках историю **не переписывают**.

---

## Простыми словами

Представь, что ты пишешь важную тетрадь, но работаешь по особым правилам.

Прежде чем что-то менять, ты делаешь **снимок страницы** и кладешь его в альбом с подписью: «Написала введение». Снимок называется **коммитом**, а номер под ним (длинный, вроде `a3f9c2`) — **хеш**. Хеш гарантирует: снимок нельзя подделать задним числом. Это **машина времени**: какую бы страницу ни испортила, у тебя есть все снимки с самого начала.

Хочешь попробовать смелую идею, не рискуя чистовиком? Ты открываешь **черновик** — отдельную ветку. Чистовик (ветка **main**) лежит нетронутым, а в черновике ты переписываешь сколько хочешь. Получилось хорошо — **вписываешь черновик в чистовик** (**merge**). Не получилось — выбрасываешь черновик, чистовик даже не узнал.

А ещё у тебя есть **облачная копия тетради** на GitHub (это **remote** — «удалённый»). Когда закончила — **отправляешь** (**push**) свои снимки в облако. Перед работой — **забираешь** (**pull**) свежие снимки коллег. Если вы с коллегой вписали разное в одну и ту же строку — возникает **конфликт**. Это не катастрофа: Git показывает оба варианта и просит тебя выбрать, какой оставить.

---

## Объяснение

### Коммит: снимок с подписью

**Commit** — точка сохранения: снимок всей папки + имя автора + время + **сообщение**. Сообщение пиши так, как будто объясняешь коллеге, *что и почему* изменилось: «Добавила форму записи к мастеру», а не «правки».

| Хорошее сообщение | Плохое сообщение |
|-------------------|------------------|
| «Переименовала колонку телефон → мобильный (миграция Ф4)» | «fix» |
| «Добавила quiz для урока Ф5» | «обновления» |
| «Откатила эксперимент с цветами кнопки» | «asdf» |

### Diff: игра «найди отличия»

**Diff** — показ разницы между двумя снимками. Читается просто:

- строки с **+** (зелёные) — добавилось;
- строки с **−** (красные) — удалилось;
- остальное — не тронуто.

Привычка смотреть diff *перед* коммитом экономит часы: ты видишь, что реально меняешь, а не что думаешь, что меняешь.

### Ветки: черновики и чистовик

**Branch (ветка)** — указатель на последний коммит. Принятая модель:

- **main** — чистовик, всегда рабочий;
- **feature-ветки** (черновики) — короткоживущие, под одну задачу: «добавить-оплату», «починить-шапку»;
- **merge** — вписать черновик в чистовик, когда задача готова и проверена.

### Remote: облачная копия тетради

**Remote** — копия репозитория на сервере (чаще всего GitHub). Два главных действия:

| Действие | Аналогия | Что происходит |
|----------|----------|----------------|
| **push** | Отправить свои снимки в облако | Твои коммиты уезжают на GitHub |
| **pull** | Забрать чужие снимки из облака | Свежие коммиты коллег приезжают к тебе |

**Конфликт** случается, когда два человека меняли одну и ту же строку. Git не выбирает за вас — он показывает оба варианта с метками и ждёт решения. Это разговор «какой вариант правильный», а не поломка.

### Безопасный откат: три способа

| Способ | Что делает | Когда уместно |
|--------|------------|---------------|
| **git revert** | Создаёт *новый* коммит, отменяющий старый | Почти всегда. История честная: «было X — стало не-X» |
| **git reset** | Стирает коммиты из истории | Только в своей личной ветке, которой никто не пользуется |
| **git restore** | Вернуть один файл к последнему снимку | «Испортила один файл — вернуть как было» |

Правило, которое стоит выучить: **в общих ветках (main) историю не переписывают**. Стертый чужой коммит — это исчезнувшая работа коллеги. Ошибся в main? Сделай **revert** — все увидят, что ты отменила, и почему.

Команды (учить наизусть не нужно — Agent запускает их за тебя):

```bash
git revert a3f9c2      # отменить коммит новым коммитом
git restore отчет.md   # вернуть один файл к последнему снимку
```

### .gitignore: «в кадр не попадает»

**.gitignore** — список файлов, которые Git игнорирует: папка `node_modules`, временные файлы, мусор. Главное — **секреты не коммитить никогда**: пароли, токены, файл `.env` с ключами. Они должны быть в `.gitignore` с первого дня (подробнее — в Ф7). Однажды попавший в историю коммитов пароль считай скомпрометированным навсегда, даже если потом удалить файл.

### Частые ловушки

1. **Один гигантский коммит «всё подряд»** — машина времени бесполезна, если снимки делаются раз в месяц: не поймёшь, что именно сломало.
2. **push --force в общую ветку** — перезаписывает историю у всех коллег; их коммиты могут исчезнуть. Почти никогда не нужно.
3. **Правки напрямую в main** — нет черновика, нет проверки; от поломанного чистовика страдают все.
4. **Пароли и токены в репозитории** — даже «временно, потом удалю»; история помнит всё (см. Ф7).
5. **Паника при конфликте** — это не поломка, а вопрос «какой из двух вариантов оставить»; спроси автора второго варианта.
6. **Коммитить «на потом» неделю работы** — чем крупнее коммит, тем страшнее его смотреть и откатывать.

## Практика

1. Создай папку для эксперимента и зайди в неё:

```bash
mkdir git-школа && cd git-школа
git init
```

2. Создай файл `план.txt` с одной строкой, сделай первый снимок:

```bash
echo "Пункт 1: выучить коммиты" > план.txt
git add .
git commit -m "Первый план"
```

3. Добавь вторую строку в файл и посмотри **diff** — что изменится:

```bash
echo "Пункт 2: выучить ветки" >> план.txt
git diff
```

4. Закоммить изменение, затем создай ветку-черновик, смени файл там и влей обратно:

```bash
git commit -am "Добавила пункт про ветки"
git checkout -b черновик
echo "Эксперимент: пункт 3" >> план.txt
git commit -am "Экспериментальный пункт"
git checkout main
git merge черновик
```

5. Откати последний коммит безопасно и убедись, что история честная:

```bash
git revert HEAD
git log --oneline
```

Всё. У тебя теперь есть папка с машиной времени, черновиком и честным откатом — ровно та же механика, что в любом рабочем проекте.

## Частые ошибки

1. **«Сначала накоплю изменений, потом закоммичу»** — коммить маленькими смысловыми шагами: снимок должен отвечать на вопрос «что тут сделано», а не «что я делала всю неделю».
2. **Исправлять чужой код молча в main** — открой черновик и предложи изменение через merge; молчаливая перезапись ломает доверие к чистовику.
3. **Пугаться конфликтов и разрешать их вслепую** — читай оба варианта и спрашивай автора, если непонятно, чей правильный.
