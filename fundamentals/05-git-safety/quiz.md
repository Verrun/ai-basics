# Quiz — Ф5. Git: коммиты, diff, ветки, remote и безопасный откат

**Порог:** ≥80% (7 из 8 правильных)

---

## Вопросы

### 1. Что такое **коммит (commit)**?

- [ ] A) Отправка файлов на сервер GitHub
- [ ] B) Удаление старых версий файлов
- [ ] C) Снимок состояния всей папки с подписью и уникальным номером
- [ ] D) Список файлов, которые Git игнорирует

### 2. Для чего смотреть **diff** перед коммитом?

- [ ] A) Чтобы увидеть, что реально изменилось: плюс — добавилось, минус — удалилось
- [ ] B) Чтобы удалить лишние файлы из папки
- [ ] C) Чтобы сгенерировать пароль к репозиторию
- [ ] D) Чтобы узнать, кто из коллег в отпуске

### 3. Ветка **main** в схеме «черновики и чистовик» — это:

- [ ] A) Мусорная корзина для удалённых файлов
- [ ] B) Чистовик: основная ветка, которая должна оставаться рабочей
- [ ] C) Архив всех старых коммитов
- [ ] D) Личная ветка каждого разработчика

### 4. Что делает **push**?

- [ ] A) Забирает чужие изменения с GitHub к тебе
- [ ] B) Создаёт новую ветку-черновик
- [ ] C) Отправляет твои коммиты в облачную копию репозитория
- [ ] D) Удаляет последний коммит из истории

### 5. Конфликт при merge возникает, когда:

- [ ] A) Два человека изменили одну и ту же строку — Git показывает оба варианта и ждёт решения
- [ ] B) Нет интернета на компьютере
- [ ] C) В репозитории больше 100 файлов
- [ ] D) Коммит слишком маленький

### 6. Какой способ отката безопасен для общей ветки (main)?

- [ ] A) git reset --hard на несколько коммитов назад
- [ ] B) git revert — новый коммит, который отменяет старый
- [ ] C) push --force, чтобы перезаписать историю
- [ ] D) Удалить папку .git и начать заново

### 7. Зачем нужен файл **.gitignore**?

- [ ] A) Чтобы ускорить загрузку репозитория
- [ ] B) Чтобы игнорировать файлы, которые не должны попадать в историю: мусор, временные файлы, секреты
- [ ] C) Чтобы автоматически форматировать код
- [ ] D) Чтобы запретить коллегам делать коммиты

### 8. Почему нельзя хранить пароли и токены в репозитории, «потом удалю»?

- [ ] A) GitHub блокирует аккаунт за любой файл
- [ ] B) После удаления файла он исчезнет навсегда без следа
- [ ] C) История коммитов помнит всё: удалённый секрет остаётся доступным по старым снимкам
- [ ] D) Пароли в репозитории мешают поиску по коду

---

## Ключ ответов

1. **C** — Коммит это снимок всей папки с подписью и хешем; отправка на сервер — это push.
2. **A** — Diff показывает разницу: строки с + добавились, с − удалились — проверь, что меняешь, до снимка.
3. **B** — main — чистовик; черновики — это feature-ветки под конкретные задачи.
4. **C** — push отправляет твои коммиты в облако; забрать чужие — это pull.
5. **A** — Конфликт это вопрос «какой из двух вариантов оставить», а не поломка.
6. **B** — revert создаёт честный отменяющий коммит; reset и force переписывают историю, что губительно в общих ветках.
7. **B** — .gitignore защищает от мусора и секретов; подробнее про секреты — в Ф7.
8. **C** — Старые снимки доступны по истории, поэтому секрет считается скомпрометированным сразу после попадания в коммит.
