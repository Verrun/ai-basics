# Quiz — Ф6. Stack trace, логи и системная отладка ошибок

**Порог:** ≥80% (7 из 8 правильных)

---

## Вопросы

### 1. Ошибка в программе — это, по сути:

- [ ] A) Сигнал начать всё с нуля
- [ ] B) Записка с адресом: где и что не так
- [ ] C) Доказательство, что программу нельзя чинить
- [ ] D) Причина немедленно удалить программу

### 2. Как читается **stack trace**?

- [ ] A) Снизу вверх, начиная с системных файлов
- [ ] B) Только последняя строка имеет значение
- [ ] C) Сверху вниз; главная строчка — первая, которая ссылается на твой код
- [ ] D) По диагонали, начиная с середины

### 3. Строка `shop.js:12:15` в stack trace означает:

- [ ] A) Ошибка случилась в файле shop.js, строка 12
- [ ] B) Файл shop.js весит 12 килобайт
- [ ] C) Программа работала 12 минут 15 секунд
- [ ] D) В проекте всего 12 файлов

### 4. Ошибка «попыталась прочитать поле у значения null» — это типичная:

- [ ] A) Синтаксическая ошибка (опечатка)
- [ ] B) Логическая ошибка (результат неправильный, но ничего не падает)
- [ ] C) Ошибка выполнения (runtime) — «позвонила по несуществующему номеру»
- [ ] D) Ошибка принтера

### 5. Уровень лога **warning** означает:

- [ ] A) Программа удалена с диска
- [ ] B) Всё идёт строго по плану
- [ ] C) Полная остановка работы, всё потеряно
- [ ] D) «Странно, но пока терпимо» — стоит разобраться до того, как станет error

### 6. Первый шаг системной отладки:

- [ ] A) Сразу менять код в пяти местах
- [ ] B) Попросить кого-нибудь перезагрузить сервер
- [ ] C) Воспроизвести ошибку стабильно: понять, при каких действиях она случается
- [ ] D) Написать агенту скриншот ошибки

### 7. Почему нельзя менять пять мест в коде сразу, чтобы «наверняка помогло»?

- [ ] A) Git запрещает коммитить больше одного файла
- [ ] B) Программа работает только при нечётном числе изменений
- [ ] C) Даже если заработает, ты не узнаешь, что именно помогло, и не сможешь повторить лечение
- [ ] D) Агент не читает большие diff

### 8. Что лучше всего прислать агенту, когда что-то сломалось?

- [ ] A) Скриншот ошибки с телефона
- [ ] B) Текст stack trace целиком + что ты делала + что ожидала увидеть
- [ ] C) Только название программы
- [ ] D) Пересказ «ну там что-то красное было»

---

## Ключ ответов

1. **B** — Ошибка это улики: тип, сообщение, файл:строка; паника тут ни при чём.
2. **C** — Читаем сверху вниз; нижние строки из библиотек часто можно пропустить.
3. **A** — Формат «файл:строка:символ» — точный адрес места поломки.
4. **C** — Чтение поля у null — классическая ошибка выполнения: программа упала посреди работы.
5. **D** — Warning это вежливый error: терпимо сейчас, опасно потом.
6. **C** — Без стабильного воспроизведения невозможно понять, вылечила ли ты что-то.
7. **C** — Одна гипотеза — одно маленькое изменение — один результат; иначе это гадание.
8. **B** — Текст ошибки — это данные, с которыми агент может работать; скриншот приходится «перепечатывать».
