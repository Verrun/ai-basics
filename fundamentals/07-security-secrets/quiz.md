# Quiz — Ф7. Основы безопасности и работа с секретами

**Порог:** ≥80% (7 из 8 правильных)

---

## Вопросы

### 1. В аналогии урока код проекта — это…

- [ ] A) Ключи от квартиры, которые нельзя никому показывать
- [ ] B) Планировка квартиры, которую можно показать кому угодно
- [ ] C) Замок на входной двери
- [ ] D) Записка с паролями в ящике стола

### 2. Что из этого является секретом?

- [ ] A) Название файла в проекте
- [ ] B) Комментарий в коде
- [ ] C) API-ключ для доступа к внешнему сервису
- [ ] D) Адрес сайта проекта

### 3. Зачем нужен .gitignore?

- [ ] A) Чтобы git работал быстрее
- [ ] B) Чтобы красиво форматировать код
- [ ] C) Чтобы перечисленные файлы (например, .env) не попадали в историю git и на GitHub
- [ ] D) Чтобы зашифровать секреты перед отправкой на сервер

### 4. Первое действие, если ты поняла, что API-ключ утёк:

- [ ] A) Удалить ключ из памяти и больше не думать об этом
- [ ] B) Написать в поддержку и ждать ответа
- [ ] C) Отозвать старый ключ в панели сервиса, чтобы он перестал работать
- [ ] D) Закрыть ноутбук и надеяться, что никто не заметил

### 5. HTTPS в аналогии урока — это…

- [ ] A) Открытка, которую читают все по пути
- [ ] B) Конверт с сургучной печатью, который по пути не прочитают
- [ ] C) Ящик стола, где хранятся ключи
- [ ] D) Спам-фильтр для писем

### 6. Принцип наименьших привилегий означает:

- [ ] A) Дать сервису все права сразу, чтобы потом не возвращаться
- [ ] B) Разрешать только тот минимум доступа, который реально нужен
- [ ] C) Не пользоваться сервисами без личного разрешения администратора
- [ ] D) Использовать один пароль везде, чтобы меньше запоминать

### 7. Почему нельзя вставлять секреты и ПДн в промпты чат-ботов?

- [ ] A) Потому что промпт тогда становится длинным
- [ ] B) Потому что бот испортит ответ
- [ ] C) Потому что модель запомнит их навсегда и перестанет работать
- [ ] D) Потому что промпт уходит на чужой сервер, и ключ легко извлечь, как с открытки

### 8. Репозиторий приватный — значит, ключи в коде коммитить можно?

- [ ] A) Да, приватность полностью решает вопрос безопасности
- [ ] B) Да, если добавить комментарий «не трогать»
- [ ] C) Нет, приватность — обещание, а не замок: доступ есть у коллег, бывают случайные приглашения и украденные аккаунты
- [ ] D) Нет, потому что git откажется принимать ключи в приватных репозиториях

---

## Ключ ответов

1. **B** — Планировку можно показывать, ключи — никогда
2. **C** — API-ключ, пароли, токены, строки подключения — это секреты
3. **C** — Список «в кадр не попадает»: .env в нём обязателен
4. **C** — Сначала закрыть дверь (revoke), потом всё остальное
5. **B** — HTTPS = конверт с печатью; HTTP = открытка
6. **B** — Ключ от детской няне, а не ключ от всей квартиры
7. **D** — Промпт уходит на внешний сервер; секреты туда не кладут
8. **C** — Правило одно для всех: ключи в git — плохо всегда
