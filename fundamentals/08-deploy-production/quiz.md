# Quiz — Ф8. Деплой, продакшен, мониторинг и бэкапы

**Порог:** ≥80% (7 из 8 правильных)

---

## Вопросы

### 1. В аналогии урока деплой — это…

- [ ] A) Написание первой черновой версии кода
- [ ] B) Перенос спектакля из мастерской на театральную сцену: код начинает работать для живых людей
- [ ] C) Удаление старой версии проекта
- [ ] D) Рисование макета будущего сайта

### 2. Для чего нужно окружение staging?

- [ ] A) Это запасная копия базы данных
- [ ] B) Это то же самое, что dev, только с другим названием
- [ ] C) Это среда, где проект видят только разработчики
- [ ] D) Это «генеральная репетиция»: проверка перед продакшеном в условиях, близких к реальным

### 3. Правильный порядок движения изменений:

- [ ] A) Production → staging → dev
- [ ] B) В любую сторону, как удобнее
- [ ] C) Dev → staging → production
- [ ] D) Сразу в production, остальное лишнее

### 4. Алерт в мониторинге — это…

- [ ] A) Автоматическое оповещение, когда метрика вышла за норму (как звонок охраны при датчике дыма)
- [ ] B) Поздравление с успешным деплоем
- [ ] C) Реклама внутри панели мониторинга
- [ ] D) Кнопка ручного перезапуска сервера

### 5. Правило 3-2-1 для бэкапов означает:

- [ ] A) 3 пароля, 2 логина, 1 почта
- [ ] B) 3 копии, на 3 разных ноутбуках, 1 облако
- [ ] C) Бэкап раз в 3 дня, проверка раз в 2 недели, хранение 1 год
- [ ] D) 3 копии данных, на 2 разных носителях, 1 копия — в другом месте

### 6. «Бэкап без проверки восстановления — это зонтик, который не раскрывается» означает:

- [ ] A) Бэкапы не нужны, лучше не мокнуть
- [ ] B) Бэкапы следует хранить в сухом месте
- [ ] C) Копия, из которой ты ни разу не восстанавливалась, может оказаться битой именно в момент ЧП
- [ ] D) Восстанавливать данные можно только в дождь

### 7. Когда нужно решать, как делать откат (rollback)?

- [ ] A) После того, как прод сломался и началась паника
- [ ] B) До деплоя, пока всё спокойно и можно всё обдумать
- [ ] C) Откат не нужен, если есть бэкапы
- [ ] D) Только если деплой происходил в пятницу

### 8. Почему нельзя править проект напрямую на проде?

- [ ] A) Потому что правки на проде работают медленнее
- [ ] B) Потому что сервер выдаёт ошибку на любое изменение
- [ ] C) Потому что это запрещено лицензией хостинга
- [ ] D) Потому что правка «живёт» только там: её никто не воспроизведёт в коде, а следующий деплой её затрёт

---

## Ключ ответов

1. **B** — Деплой = перенос на сцену, где код видят живые люди
2. **D** — Staging = генеральная репетиция перед премьерой
3. **C** — Всегда dev → staging → production
4. **A** — Оповещение при выходе метрики за норму
5. **D** — 3 копии / 2 носителя / 1 копия в другом месте
6. **C** — Непроверенный бэкап может не сработать именно тогда, когда нужен
7. **B** — План отката пишется до деплоя, а не в панике
8. **D** — Правка вне кода не воспроизводится и затирается следующим деплоем
