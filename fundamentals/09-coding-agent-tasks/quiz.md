# Quiz — Ф9. Как ставить задачи кодинг-агенту и проверять его результат

**Порог:** ≥80% (7 из 8 правильных)

---

## Вопросы

### 1. В аналогии урока кодинг-агент — это…

- [ ] A) Гадалка, которая знает твои желания без слов
- [ ] B) Компилятор, который чинит любой код автоматически
- [ ] C) Словарь, по которому ты разговариваешь с компьютером
- [ ] D) Толковый подрядчик, который умеет работать, но не читает мысли

### 2. Что должно быть в хорошем заказе агенту?

- [ ] A) Только цель: «сделай красиво»
- [ ] B) Контекст, цель, критерии готовности, ограничения и способ проверки
- [ ] C) Список файлов, которые агенту нельзя открывать
- [ ] D) Пожелание удачи и эмодзи

### 3. Почему заказ «сделай сайт лучше» — плохой?

- [ ] A) Потому что агент откажется работать без точного названия сайта
- [ ] B) Потому что в нём слишком много слов
- [ ] C) Потому что «лучше» не определено — агент угадает своё, и тебе не понравится
- [ ] D) Потому что такие заказы запрещены правилами git

### 4. Как правильно декомпозировать большую задачу?

- [ ] A) Дать её агенту целиком, но срочно
- [ ] B) Поделить на один заказ в день, чтобы не перегружать агента
- [ ] C) Разбить на список маленьких задач: одна задача = одно изменение
- [ ] D) Попросить агента сам угадать, из чего состоит задача

### 5. Что такое diff и зачем его читать?

- [ ] A) Это список пожеланий агента; читать не обязательно
- [ ] B) Это сравнение изменений в коде; читаешь, чтобы увидеть, что именно агент поменял, до принятия работы
- [ ] C) Это журнал ошибок; его читает только агент
- [ ] D) Это файл с секретами проекта

### 6. Что нужно показать агенту при ошибке в проекте?

- [ ] A) Текст stack trace целиком, логи и шаги воспроизведения
- [ ] B) Скриншот ошибки с телефона
- [ ] C) Достаточно написать «не работает»
- [ ] D) Ничего — агент сам должен догадаться, что сломалось

### 7. Какой из этих вариантов опасно принимать у агента без проверки?

- [ ] A) Добавление комментария в код
- [ ] B) Переименование переменной по соглашению проекта
- [ ] C) Команду push --force и предложение удалить файлы
- [ ] D) Исправление опечатки в тексте кнопки

### 8. Если агент сделал не то, что ты хотела, первым делом нужно…

- [ ] A) Удалить проект и начать заново
- [ ] B) Написать агенту гневное сообщение
- [ ] C) Проверить свой заказ: чего не хватило — контекста, критерия, ограничения — и уточнить задачу
- [ ] D) Никогда больше не пользоваться агентами

---

## Ключ ответов

1. **D** — Подрядчик без телепатии: качество ответа = качество заказа
2. **B** — Пять частей: контекст, цель, критерии, ограничения, проверка
3. **C** — Неопределённый заказ = угадывание, переделки и потерянное время
4. **C** — Одна задача = одно изменение; каждый шаг проверяется отдельно
5. **B** — Diff показывает факт изменений; принимать работу не глядя нельзя
6. **A** — Текст ошибки целиком + логи + шаги воспроизведения
7. **C** — Опасные команды (force push, удаление) всегда согласовывай глазами
8. **C** — Ошибка агента — диагностика ТЗ: допиши недостающее и крути петлю
