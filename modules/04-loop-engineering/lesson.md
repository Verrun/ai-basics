# М4. Loop engineering

## За 2 минуты

**Loop** — AI работает по кругу: подумал → сделал → проверил → повторил. **Loop engineering** — правила: когда продолжать, когда стоп, кто проверяет.

---

## Объяснение

### Loop (цикл агента)

**Термин:** loop — повторяющийся цикл действий AI.  
**Аналогия:** *повар пробует блюдо → добавляет → пробует снова.*

```
План → Действие → Результат → Проверка
         ↑                           |
         └──── ещё не готово ────────┘
```

Один промпт = один ответ. Loop = много итераций до результата.

### Loop engineering

**Термин:** loop engineering — проектирование control flow.  
**Аналогия:** *правила игры: сколько попыток, кто проверяет, когда зовём человека.*

Вопросы loop engineering:
- Когда AI делает ещё одну попытку?
- Когда останавливается?
- Кто проверяет результат?
- Что делать при ошибке?

### ReAct (Reason + Act)

**Термин:** ReAct — паттерн «рассуждай → действуй → наблюдай».  
**Аналогия:** *подумал → сделал → посмотрел → подумал снова.*

Пример: AI ищет в Google → читает страницу → решает искать ещё → собирает ответ.

### Maker / Checker

| Роль | Задача |
|------|--------|
| **Maker** | Создаёт результат |
| **Checker** | Проверяет по фактам, не по «мне кажется» |

Checker — ты, коллега или **отдельный** AI с другими инструкциями.  
Не «AI проверяет сам себя» — это не независимая проверка.

### Лимиты и стоп

- **Max попыток** — например, 5 итераций
- **Стоп-условие** — «найдено 3 независимых источника»
- **Эскалация** — после N неудач → человек

### Cursor: /loop и Automations

- `/loop 5m проверь статус деплоя` — AI вернётся через 5 минут
- **Automations** — повторяющиеся задачи по расписанию

---

## Частые ошибки

1. **Один промпт на сложную задачу** — нужен loop с проверками.
2. **AI проверяет сам себя** — «всё ок» без фактов.
3. **Нет лимита попыток** — AI может крутиться бесконечно.
