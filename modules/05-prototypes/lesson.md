# М5. Прототипы в вёрстке

## За 2 минуты

Опиши экран словами → AI создаёт HTML-страницу → открываешь в браузере. HTML учить не нужно — это результат работы AI.

---

## Объяснение

### От идеи к экрану

**Pipeline:**
```
Текстовое ТЗ → AI (Cursor) → index.html → Браузер
```

**Prototype (прототип)** — черновая версия для проверки идеи, не финальный продукт.  
**Аналогия:** *макет кухни из картона — видно расположение, но не настоящая плита.*

### Инструменты

| Инструмент | Как работает |
|------------|--------------|
| **Cursor** | Описала → AI создаёт файл |
| **Figma MCP** | Слайды и макеты из Cursor |
| **v0 / Lovable** | No-code прототип в браузере |
| **Chrome DevTools MCP** | AI проверяет вёрстку на живой странице |

### Хорошее ТЗ на макет

Укажи:
- **Тип:** одна страница, лендинг, мобильная версия
- **Секции:** hero, features, footer, кнопка CTA
- **Стиль:** цвета, настроение (минимализм, яркий)
- **Контент:** заголовок, подзаголовок, текст кнопки

**Пример:** «Одностраничный лендинг для приложения доставки еды. Мобильная вёрстка. Hero: заголовок "Еда за 30 минут", кнопка "Заказать". Секция с 3 преимуществами. Цвета: зелёный и белый.»

### Итерации

Не жди идеал с первого раза:
- «Крупнее заголовок»
- «Добавь секцию с отзывами»
- «Сделай кнопку зелёной»

Каждая итерация — один чёткий запрос.

### HTML как результат

**HTML/CSS** — языки вёрстки. В курсе ты **не учишь** их — AI создаёт файл, ты **смотришь** в Chrome.

---

## Практика

1. Открой [exercises/prototype-brief.md](../../exercises/prototype-brief.md).
2. Заполни ТЗ на лендинг вымышленного продукта.
3. В Cursor (Agent mode): «Создай index.html по этому ТЗ».
4. Открой `index.html` в браузере.
5. *(Опционально)* Chrome DevTools MCP: «Проверь, почему [элемент] выглядит не так».

---

## Частые ошибки

1. **Размытое ТЗ** — «сделай красивый сайт» → много итераций.
2. **Ждать идеал с первого промпта** — прототип = черновик.
3. **Бояться HTML** — ты не редактируешь код, ты просишь AI.
