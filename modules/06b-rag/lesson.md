# М6b. RAG-поиск

## За 2 минуты

**RAG** — модель сначала **ищет** нужные куски в *твоих* документах, потом отвечает по ним. Не «из головы», а по шпаргалке. Так меньше выдумок про внутренние правила и регламенты.

---

## Простыми словами

Представь: у тебя на полке лежит папка с инструкциями компании. Ты спрашиваешь: «Какой у нас дедлайн по отчёту?»

Без RAG модель отвечает «из памяти» — может красиво выдумать.  
С RAG система делает так:

1. Берёт твой вопрос.
2. Находит **2–5 самых похожих абзацев** из твоих файлов.
3. Кладёт их рядом с вопросом как шпаргалку.
4. Модель отвечает **по этой шпаргалке** (и лучше — со ссылкой на файл).

Это и есть **RAG** = *Retrieval-Augmented Generation*  
(*поиск + дополнение + генерация*).

**Аналогия:** библиотекарь достаёт нужные страницы из *твоей* полки и кладёт их на стол — писатель читает их и только потом пишет ответ.

## Объяснение

### Зачем RAG, если есть интернет и чат

| Способ | Откуда знание | Когда уместно |
|--------|---------------|---------------|
| **Только LLM** | «Память» модели | Идеи, черновики, пересказ того, что уже в чате |
| **Поиск в интернете** (М6) | Сайты снаружи | Новости, тренды, чужие статьи |
| **RAG** | *Твои* PDF, Notion, vault, база знаний | Регламенты, FAQ продукта, внутренние гайды |

RAG не заменяет fact-check и не делает модель «всезнающей». Он даёт ей **доступ к нужным кускам твоих материалов**.

### Как устроен пайплайн (без кода)

1. **Документы** — PDF, markdown, Notion, заметки Obsidian.
2. **Нарезка (chunks)** — длинный текст режут на короткие куски (абзацы/страницы).  
   *Почему:* в запрос нельзя впихнуть всю энциклопедию сразу.
3. **Смысловой отпечаток (embedding)** — каждый кусок превращают в набор чисел «о чём это».  
   *Аналогия:* не ключевое слово «отчёт», а «похоже по смыслу на дедлайны и отчётность».
4. **Индекс / векторное хранилище** — полка, где лежат эти отпечатки, чтобы быстро искать похожее.
5. **Вопрос → поиск** — система находит ближайшие куски.
6. **Ответ** — модель генерирует текст **с опорой на найденное**.

Тебе не нужно писать этот пайплайн руками. Важно понимать **порядок**: сначала найти, потом отвечать.

### Chunk, embedding, индекс — коротко

| Термин | Простыми словами |
|--------|------------------|
| **Chunk** | Кусок текста (не весь файл целиком) |
| **Embedding** | «Смысловой отпечаток» куска — числа, по которым ищут похожее |
| **Индекс / vector store** | Склад отпечатков + быстрый поиск «что рядом по смыслу» |
| **Retrieval** | Шаг «найти куски» |
| **Augmented generation** | Шаг «ответить, глядя на найденное» |

### RAG vs «закинуть весь PDF в чат»

| | Весь файл в чат | RAG |
|--|-----------------|-----|
| Маленький PDF (5–10 стр.) | Часто ок | Избыточно |
| Сотни страниц / много файлов | Не влезет / дорого | Как раз для этого |
| Ответ | Может «потерять» середину | Тянет только релевантное |
| Повторные вопросы | Каждый раз грузить заново | Индекс живёт отдельно |

**Правило:** один короткий документ — приложи к чату. Библиотека документов — RAG (или vault + MCP, который умеет искать).

### Где ты уже встречаешь похожее

- **Cursor** по коду проекта: ищет нужные файлы, потом правит — идея та же, что у RAG (сначала найти контекст).
- **Obsidian + MCP:** AI читает vault; хороший поиск по заметкам ≈ «домашний RAG».
- **ChatGPT / Claude с Knowledge / Projects:** загружаешь базу — сервис сам режет и ищет.
- **Корпоративные боты** «спроси HR-бота» — почти всегда RAG по внутренним PDF.

### Частые ловушки

1. **Плохие документы** — мусор на входе → мусор в ответе. RAG не чинит кривые регламенты.
2. **Слишком крупные chunks** — находит «почти то», но тонет в лишнем тексте.
3. **Нет ссылок на источник** — проси: «цитируй файл и абзац»; иначе снова галлюцинации.
4. **Путать с веб-поиском** — RAG ≠ интернет. Для новостей — М6; для внутренних правил — RAG.

## Практика

1. Открой [exercises/rag-brief.md](../../exercises/rag-brief.md).
2. Собери **мини-базу** из 3–5 своих текстов (заметки, FAQ, выдержки из гайда — без секретов).
3. Задай один и тот же вопрос:
   - **без** документов (только модель);
   - **с** документами (чат с файлами / Cursor / Obsidian MCP).
4. Сравни: откуда факты, есть ли выдумки, удобно ли найти источник.

---

## Частые ошибки

1. **Ждать правду «потому что RAG»** — если кусок не нашёлся, модель всё равно может додумать.
2. **Кормить паролями и ПДн** — те же правила конфиденциальности, что в М1.
3. **Делать RAG ради RAG** — для одного письма в чат достаточно прикрепить файл.
